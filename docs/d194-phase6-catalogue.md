## Heuristic

- Scanned: `.ts`, `.tsx`, `.mjs` under `app/`, `components/`, `lib/`, `scripts/`, `etc/` (if present).
- Excluded: `node_modules`, `.next`, `.claude`, `__fixtures__`, `vendor`, `*.test.ts(x)`, `*.d.ts`, and this script.
- Collected: string literals, template literal text chunks (each chunk on its own) and JSX text. Comments and import/export specifiers are ignored.
- A string counts as Slovak/Czech when it contains a diacritic from the Slovak/Czech set, or at least 2 words from a short list of common Slovak words (je, sa, nie, pre, ale, alebo, ako, pri, bez, musi, nebol, zlyhalo, ...). Slovak strings without diacritics and with fewer than 2 such words are not found, so counts are a lower bound.
- Classification per file (first match wins):
  - **AI**: reaches the AI assistant (system prompts, tool descriptions, tool results and errors): `lib/llm/**`, `lib/mcp/**`, `app/api/mcp/**`, `lib/engine/tool-defs*`, `**/tools*.ts`, `**/*-tools.ts`, tool-registry files, MCP-TOOLS sources, `lib/feedback/*tool*`.
  - **USER**: UI text shown to people: `components/**`, app pages, and `app/api/**` route messages returned to the browser.
  - **LOG/CLI**: console output of `scripts/**` (and `etc/**`).
  - **OTHER**: everything else (for example `lib/engine/**` outside tool-defs, `lib/viewer-*.ts`). These may still end up in AI or UI output indirectly and need a manual look in phase 6.
- Examples are the first 2 matching strings per file in source order, cut to 100 characters, with typographic punctuation normalised to ASCII.

## Data contract: do NOT translate

Strings that are part of the data contract and must stay as they are (the list is based on what is obvious from the code, not exhaustive):

- Verification status enum values such as `overene` and `vratene` (and the other status values stored in the database and compared in code).
- The requirement/object field name `narocnost` and other ASCII-folded Slovak column names and jsonb keys (they are keys, not display text).
- Database table and column names, jsonb keys, RPC names and enum labels in `supabase/` migrations and in `SCHEMA.md`.
- MCP tool names and their argument names (the registry in `lib/mcp/tool-registry.json` and `MCP-TOOLS.md`): the names are identifiers, only the descriptions are text.
- Keys of JSON objects returned by routes and tools, query-string parameter names, and IFC property set / property names looked up in model data.
- Values read from model data or the library (for example Slovak property values in IFC files): they match data and are not UI text.
