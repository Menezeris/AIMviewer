- Navigable tree; selecting a space -> the assets in it.

**S2 - Asset card (core of interlinking)** ✅ (D-028)
- Read `v_asset_effective` (merge + inheritance), `v_asset_classifications` (facet union).
- Properties grouped by pset; `Pset_`/`Qto_` = standard, the rest = custom; `_keys` hidden.

- Acceptance ✅: AHU-01 shows `AirFlowRate:4800` (override) + inherited from the type + both classifications.

**S3 - Documents + responsibilities** ✅ (D-029)
- `rel_associates_document` -> `documents`; `rel_assigns_to_actor` (role, validity) + `rel_member_of`.
- `ifc_guid_history` panel (active + archived). Sections generic on every node.
- Generic object route `/node/[id]` (person/organization/document detail) + two-way
  cross-linking; `asset_type` -> redirect to `/type/[id]`.
- Acceptance ✅: on AHU-01 you can see the manual (link), Ján Novák (operator, member of TZB Servis)
  and 2 GUID records; a click on the person -> his 2 responsibilities + membership; a click on the document ->
  "attached to AHU-01".
- Polish (D-030): sidebar nav to types/persons/organizations/documents; ISR cache
  (`unstable_cache`, revalidate 60 s) + `loading.tsx` - TTFB on Vercel ~1.9 s -> ~0.3 s.

**S4 - Polish & launch**
- Depends on the ETL branch (real data). Domain + public launch (D-007 open question).

**S5 - IFC 3D viewer** ✅ phases 1-3 done (D-044)
> Parallel branch - merged into `main` 2026-06-28. Assumption: the GUIDs in the DB correspond to the
> rendered IFC. The E2 ETL loaded ASR.ifc -> trivially satisfied; the same file is used for
> rendering and as the source of GUIDs in the DB (D-044, intentional). Route `/ifc` (`app/(viewer)/ifc/page.tsx`),
> render `components/ifc-viewer.tsx`, orchestration `ifc-workspace.tsx`, GUID map `lib/data/ifc.ts`.

  embedded in the Viewer; displays ASR.ifc client-side (`exportGlb` -> GLTFLoader). An isolated
  module (`ssr: false`) - its crash does not bring down the data viewer. WASM self-hosted from `public/`.
- **Phase 2 - Two-way selection ✅** *(target demo moment):* a click/raycast on an element in 3D ->
  asset card (`/node/[id]`) in the side panel + highlight; `?focus=<guid>` from the card/tree ->
  highlight + zoom in 3D. Link = IFC GUID (`exprToGuid` from the STEP text <-> `guidMap` from
  `ifc_guid_history`). Touch picking on mobile. The mapping function is reusable for phase 3.

  two-way DB<->3D filter bar (`components/filter-bar.tsx`, `/api/filter`, `lib/data/filter.ts`),
  spatial context of the picked element (`/api/space-siblings`), Escape = clear selection. The authority
  of the query stays in the DB (`v_asset_effective`, D-028).
- **Guardrails:** Postgres does not touch geometry (no mesh/cache in the DB); pinned version of
  IFClite (not `latest`); Three.js WebGL template (not WebGPU).
- Acceptance ✅ (phase 2): a click on a specific door in 3D -> asset card with provenance,
  responsibilities, drawing; a click in the tree -> highlighted in 3D. DB schema **does not change**.
